## Why this exists

Most software showcases today are flooded with AI wrappers, ChatGPT clones, and prompt engineering demos. Hackathon builders are different. They ship real things under real pressure -- hardware that bends physics, protocols that rethink how money moves, tools that make developers faster, and products built for people who actually need them. This repo collects those projects. It pulls directly from the Devfolio API, organizes by theme, and updates every 24 hours so nothing gets buried.

## How AutoFlow AI Fits the Open Track

AutoFlow AI is a general-purpose agentic execution platform designed to turn natural-language intent into complete, reliable workflows.

Unlike solutions built for a single domain, AutoFlow can be applied across a wide range of use cases — from research and data processing to software development, productivity, business operations, and multi-step digital tasks.

A user simply describes **what they want to accomplish**, while AutoFlow handles the complexity behind the scenes:

- **Intent Understanding** — interprets the user's goal, constraints, and requirements.
- **Intelligent Planning** — breaks complex goals into structured, executable steps.
- **Agent & Model Orchestration** — dynamically selects the appropriate agents and AI models for each task.
- **Tool Execution** — connects workflows with APIs, applications, browsers, and other tools.
- **Governance** — applies permissions, policies, budgets, and human approval where required.
- **Verification** — checks whether actions actually produced the expected results.
- **Recovery** — detects failures and can retry, recover, or re-plan instead of simply stopping.
- **Observability** — makes the execution process visible and traceable to the user.

This makes AutoFlow a flexible foundation for building many kinds of AI-powered workflows without requiring users to manually design every step, select agents, or understand the underlying orchestration.

The **Open track** is a natural fit because AutoFlow is not solving just one narrow problem — it introduces a general framework for moving from **human intent to verified execution** across different domains.

**Software**

**CoEvolve Sandbox** fits strongly within the Open Innovation track by addressing an emerging challenge at the intersection of Generative AI, autonomous software development, and cybersecurity. As AI coding agents become increasingly capable of writing and modifying software, ensuring that their outputs remain secure is a continuously evolving problem. Our project proposes an innovative, self-improving security framework that allows coding agents to learn from verified failures without retraining their underlying models.

The system creates a continuous attacker–developer co-evolution loop: an Attacker LLM generates adversarial coding tasks, a Developer LLM attempts to solve them, and a Hybrid Judge validates vulnerabilities using both static analysis (SAST) and dynamic exploit replay (DAST). Confirmed failures are transformed into natural-language security rules and incorporated into the developer agent's system prompt. This creates a non-parametric alignment mechanism where defensive capabilities evolve while model weights remain frozen.

The project demonstrates innovation through adaptive Elo-based difficulty, hardened Docker isolation, regression guarding, Git-backed prompt evolution, and portable security rules. It already supports multiple LLM providers, three programming languages, 29 SAST rules, and 19 vulnerable applications for DAST validation.

Therefore, CoEvolve is not simply another cybersecurity scanner; it is an **adaptive innovation platform for continuously improving the security of autonomous AI coding systems**, with potential to evolve alongside new models, attack techniques, and software environments.

**Software**

BioVolt is designed as a reusable, collaborative experiment platform rather than a one-off hardware prototype.

It uses a common telemetry format, modular backend, simulator, database, and dashboard so researchers and developers can:

- Connect different microbial-cell and sensor designs
- Reuse the same data-processing pipeline
- Add new biomass, OD680, carbon-fixation, or optimization models
- Test ideas through simulation before hardware is available
- Compare experiments using consistent data structures
- Extend the platform without redesigning the entire system

The software is the measurement and visualization layer around the physical BioVolt hardware:

```text
BioVolt cell + sensors
        ↓
ESP32 firmware
        ↓ USB serial / COM5
ESP32 serial bridge
        ↓ WebSocket
Backend
        ↓
Dashboard
```

- The hardware produces the real signal: electrodes generate BPV voltage/current, ADS1115 reads BPV and BPW34, BH1750/GY-302 reads light, and DS18B20 reads temperature.
- The ESP32 firmware reads those sensors and sends raw values plus health status.
- The serial bridge transports the ESP32 frames to the backend.
- The backend validates data, applies calibration, calculates current, power, energy, OD680, biomass, and carbon fixation, then stores and broadcasts the results.
- The frontend displays live values and graphs.

The simulator is only a pre-hardware substitute. Its PWM-like spikes and load-sag model help test the dashboard before or between hardware runs; they are not evidence that the real cell is producing spikes.

For the hardware track, the remaining validation is physical:

- Verify wiring and sensor health.
- Connect and measure the real electrical load.
- Calibrate voltage/current against the multimeter.
- Capture proper BPW34 dark and blank references for OD680.
- Compare sustained ESP32 readings against the dashboard.
- Run the system for an extended period to check noise, drift, and connection stability.

A software load setting changes calculations; it cannot physically reduce the ESP32 circuit voltage. The real voltage drops only when the load is connected to the hardware circuit.

# Track Submission: Open Innovation / Open Track

### Project Title
**SentinelX — Autonomous Local-First DevSecOps with Dual-Agent Self-Healing Architecture**

---

### Track Fit & Overview
In the **Open Track**, innovation is judged by tackling systemic industry bottlenecks with novel engineering, unconstrained by narrow problem statements. SentinelX re-engineers modern application security by eliminating the trade-off between **privacy, operational cost, and autonomous remediation**. 

Most modern security platforms (like GitHub Copilot Autofix, Snyk, or Veracode) treat code analysis as a cloud-dependent service. This forces companies with proprietary codebases, healthcare data, or defense contracts to leak IP to third-party APIs while paying steep SaaS premiums. Furthermore, existing tools remain passive: they produce raw alerts, inundating developers with false positives, while leaving the remediation burden entirely manual.

SentinelX introduces an entirely autonomous, closed-loop DevSecOps system running **100% locally on commodity consumer hardware**. By pairing a static analysis-driven **AI Red Team** (for discovery and noise filtering) with a verified **AI Blue Team** (for syntax-validated in-place self-healing and Pull Request automation), SentinelX transforms security from a reactive bottleneck into an invisible, self-contained development partner.

---

### Core Innovation & Uniqueness
1. **Zero-Data-Exfiltration DevSecOps:**
   SentinelX executes both discovery and remediation fully air-gapped using local small language models (`qwen2.5-coder:7b` via Ollama) and local CLI static scanners. No line of source code, secret key, or repository metadata ever touches an external server.

2. **Dual-Agent Closed Loop (Red vs. Blue):**
   * **The Red Team:** Gathers scanner signals (Semgrep, Gitleaks, Trivy) and uses contextual AI reasoning to drop false positives (e.g., test tokens or mock database strings). It models modern attack surfaces (SQLi, Command Injection, Insecure Deserialization, XSS, and simulated IDOR/CSRF) into persistent telemetry streams.
   * **The Blue Team:** Takes verified exploits, writes contextual patches, validates structural syntax using local language runtimes (`ast.parse` and `node --check`), writes a safe `.bak` disk backup, and autonomously pushes a branch and GitHub Pull Request with AI-generated developer notes.

3. **Deterministic Safety Architecture:**
   AI agents should never write broken code into production. SentinelX implements a multi-tier fallback mechanism:
   * **Parser Verification:** Hallucinated syntax is blocked at the AST level before writing to disk.
   * **Rule-Based Fail-Safes:** If local hardware encounters memory limits or Ollama timeouts, deterministic rule-based engines (`RULE_BASED_FALLBACK_ENGAGED`) guarantee successful patch delivery.
   * **CLI Portability:** Missing host binaries seamlessly hand off to heuristic regex engines (`HEURISTIC_FALLBACK_ENGAGED`).

---

### Technical Architecture
* **AI & Remediation Engine:** FastAPI (Python 3.11+), Ollama (`qwen2.5-coder:7b`), AST compiler tools, and Server-Sent Events (SSE) telemetry pipelines.
* **Scanning & Detection:** Semgrep rulesets, Gitleaks entropy scanners, Trivy vulnerability databases, and internal heuristic regex fallback engines.
* **Authentication & Integrations:** Node.js / Express microservice handling granular GitHub OAuth token workflows and Octokit PR creation.
* **Frontend & Operations Console:** Next.js / React interactive dashboard visualizing live Red Team attack telemetry, vulnerability triage graphs, real-time code diffing, and automated PR deployment statuses.

---

### Impact & Scalability
* **Cost Disruption:** Zero recurring API token costs. Startups and enterprise teams can run continuous security audits on standard developer laptops or self-hosted CI/CD runners at zero marginal cost.
* **Velocity Multiplier:** Reduces vulnerability triage and patching cycle time from an industry average of **15–20 days to under 30 seconds**.
* **Ecosystem Agnostic:** Expandable across languages (Python, JavaScript/TypeScript, Go, Rust) by simply registering language-specific syntax validation checkers into the Blue Team pipeline.

---

### Future Roadmap
* **CI/CD Action Runner:** Package SentinelX as a self-hosted GitHub Action / GitLab Runner container for air-gapped enterprise pipelines.
* **Multi-File Context Graphing:** Extend the Blue Team's AST analyzer to resolve cross-file import dependencies when patching distributed vulnerabilities.
* **Dynamic Ephemeral Sandboxing:** Spin up isolated Docker containers to dynamically verify exploit payloads before and after Blue Team patch application.
